# DIY-001 — Scientific engineering methodology

Revision 0.1 · proposed

## Four layers
1. Convention: notation, units, domains, axioms, calibration and assumptions.
2. Written expression: original claim, mathematical transcription, algorithm and implementation.
3. Proved relationship: analytical derivation, proof artifact and checker result, each distinguished.
4. Physical record: observation, calibration record, experiment and provenance. Synthetic records are not physical evidence.

## Workflow
1. Register source version, locator, hash, rights and exact claim location. Do not redistribute without permission.
2. Preserve original claim; separately record formal transcription, assumptions, corrections, counterexamples and proposed extensions.
3. Define mathematical obligations and acceptance criteria. Check domain restrictions and definedness.
4. Select proof route: existing RLT fragment, Lean/Mathlib, analytical proof, computational test or open obligation. Never silently add a premise or substitute finite tests for general proofs.
5. Derive engineering interfaces and invariants. Build minimal reference implementation and tests; pin dependencies and record commit and commands.
6. Independently audit source fidelity, theorem statements, code correspondence, negative tests and checker results. Proof of a model is not proof of its implementation without a correspondence argument.
7. Plan physical tests with controls, independent outcomes, uncertainty, stop conditions and permissions. Record evidence and revise claims.
8. Offer author-controlled handoff: source register, roadmap, repository setup, prompts, verification instructions and limitations. Agree scope, rights, funding and ownership before product-specific work.

## Generalization rule
Promote demonstrated reusable engineering patterns to DIY; propose general proof-language extensions in RLT separately, with soundness justification, regression tests and independent review. Never import application hypotheses as kernel axioms merely to make a claim pass.
